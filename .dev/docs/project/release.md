# Next Release

## Overview

The next release establishes `code-worker` as a reusable, validated template
baseline. It packages the local development-control structure and its core
skills so a target codebase can begin with explicit planning, requirements,
validation, and evidence without carrying target-specific implementation.

## Overall Requirements

- It must include the established `.dev/` documentation structure for the project plan, architecture, release, roadmap, module requirements, module QA, and indexes.
- It must maintain Title, Tagline, Core Proposition, and Key Ideas in each target project plan as the source for its user-facing documentation and project index.
- It must use `maintain-requirements` to create each target module requirements record with the GraphK-style Req_id, Description, Verification, Test Unit, and Status table.
- It must use `validate-module` to create each target module QA with the standard Summary, Validation Execution, Requirement Traceability, and Executed Test Units layout.
- It must include the validated core skills for skill creation, requirements maintenance, module validation, code documentation, index maintenance, README maintenance, and skill validation.
- It must require all managed skills to use the authoritative minimal, well-described skill format and current QA evidence.
- It must keep skill and project indexes derived from their current plans and QA records.
- It must exclude target-product implementation and target-specific requirements that do not belong in a reusable template.
- It must preserve `.dev/` as local-only development control and leave GitHub synchronization as a manual action.
- It must pass the complete core-skill validation and executable test suite before the release is considered ready.
