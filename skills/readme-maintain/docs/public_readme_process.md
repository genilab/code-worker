# Public Release README Process

Use this process when `AGENTS.md` declares `README profile: public-release`.

1. Read the project purpose, verified public capabilities, repository URL, and
   approved public actions from the project's maintained records.
2. Populate the title and one-line description with verified wording only.
3. Add an infographic only after an approved image exists in `assets/images/`
   and the asset-agent has handed it off for public documentation. Otherwise,
   state that no infographic is published for the release; never add a
   speculative image or broken asset reference.
4. Add only badges backed by public, current facts. Prefer a GitHub Release
   badge when releases exist; omit unsupported badges.
5. Explain what the project does and list only verified differentiators.
6. Provide tested clone-and-enter commands for the repository.
7. List the next public operations and exact commands or concise instructions.
8. Before an explicit GitHub commit, recheck every URL, badge, command, and
   public claim. Preserve the section order in the public-release template.
